## 移动用户搜 CMIN2，通常都是被 CN2 GIA 坑过一次

电信的 CN2 GIA、联通的 AS9929，这两个词在 VPS 圈子里被念了太多年。问题是，它们跟移动宽带没有半点关系。你用移动的线路出国，走的是移动自己的骨干，服务器那头没做针对性路由，你花高价买的"顶级线路"照样在晚上八点开始抖。

所以当一个人开始搜"移动 CMIN2 VPS"，他大概率已经交了学费，现在想搞清楚三件事：CMIN2 到底是不是真的、我怎么自己验证、哪家的套餐值得买。

这三个问题按顺序解决，比看十篇测评有用。

## CMIN2 到底是什么：记住 AS58807 就够了

CMIN2 的全称是 China Mobile International Network 2，中国移动国际的第二代跨境精品网络，对应的自治系统号是 AS58807。

这里有个高频混淆点。移动的国际出口有两条完全不同的东西：普通的 CMI 走 AS58453，属于常规国际互联；CMIN2 走 AS58807，在骨干层面带专门的路由标识和优先级，跨运营商互联时排队更少、绕路更少。两者都属于移动系统，但等级和晚高峰表现差得远。网上把 CMIN2 写成 AS58453 的文章不少，看到直接跳过就行。

### 自己动手，两步验完

不用装复杂脚本，两个方法就够：

1. 已经有机器的，SSH 登录后执行 `traceroute` 到你家所在省份的移动 IP（没有 traceroute 先 `apt install traceroute`）。把输出里每一跳的 IP 拿去查 ASN，链路中出现 **58807**，才说明真的接入了 CMIN2。
2. 还没买的，用 ITDOG 这类多线路测速平台，输入目标 VPS 的 IP，勾选几个省份的移动节点做路由跟踪，看路径里有没有 58807，顺带看丢包率。

这两步做完，商家的宣传语基本就不用看了。

## 真 CMIN2 的回程应该长什么样

拿一份 2025 年 11 月对 DMIT 洛杉矶 EB 机型的实际测试数据当参考。北京移动的回程是这样的：


AS906（DMIT 骨干）→ AS58807 [CMIN2-NET] 洛杉矶
→ AS58807 中国上海 → AS9808 [CMNET] 上海/北京


洛杉矶到上海 CMIN2 段落大约 126ms，落到北京最终在 152ms 左右。上海移动全程 126—130ms，广州、北京、上海三地的 TCP 大包延迟分别在 162/152/128ms 区间。同一份测试里，电信和联通回程走的是 AS10099 → AS9929 这条 CUII 精品线。

这个数据结构说明一件事：移动流量被明确地交给了 58807，不是"移动用户也可以访问"这种模糊说法。

顺便提一句，这份测试的机器用的是 AMD EPYC 9654，磁盘大块读写 1 GB/s 上下，sysbench 单核四千分出头的水平，对这个价位的机器来说硬件不是瓶颈。

## 几个被问得最多的问题

**CMIN2 和 CN2 GIA 哪个更好？**
不是同一维度的对比。CN2 GIA 是电信的线路等级，CMIN2 是移动的。对移动用户来说，CMIN2 是更直接相关的那个；对电信用户来说，CN2 GIA 才是重点。所以"哪个更好"取决于你的宽带运营商。

**EB 系列的 IPv6 也走 CMIN2 吗？**
是的。2025 年的实测报告里，北京、上海、广东移动的 IPv6 回程同样显示为 AS58807 CMIN2。IPv6 段的表现和 IPv4 大体一致，某些地区甚至更好。

**延迟大概多少？**
洛杉矶机房到国内移动，华东华南华北普遍在 126—170ms 区间，属于美西优化线路的正常水平。真正的差别不在平均延迟，而在晚高峰的波动幅度——这也是 CMIN2 存在的意义。

**可以先测试再买吗？**
可以。官方提供 Looking Glass 页面，能实时 ping 和看路由，另外有公开测试 IP 可用。买之前自己跑一遍 traceroute 确认 58807 在不在链路里，是最省事的验证方式。
